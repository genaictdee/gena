# Assignment 2.10 Break It Fix It and Validate It

This project demonstrates debugging an intentionally malformed HTML profile page. It includes the unchanged original, the corrected version, manual findings, a problem/fix table, initial and final W3C reports and readable validation screenshots.

Public project: https://github.com/genaictdee/gena/tree/main/assignment-2.10-debugging

## Files to review

- broken.html — the intentionally malformed original, preserved byte for byte after creation.
- fixed.html — the corrected complete document.
- manual-diagnosis.md — the source inspection recorded before the checker run.
- problem-fix-table.md — 16 specific problems, exact source locations, fixes and reasons.
- screenshots/initial-validation.png — the initial checker result showing errors and a warning.
- screenshots/final-validation.png — the successful final checker result.
- validation/initial-w3c-report.json and validation/final-w3c-report.json — original machine-readable checker responses.
- validation/initial-w3c-report.html and validation/final-w3c-report.html — unmodified human-readable HTML responses returned by the hosted checker.
- validation/summary.json — check dates, checker version, counts and final source hashes.
- validation/source-fingerprints.json — the original broken-file fingerprint and the fixed-file fingerprint.
- browser-checks.json — verification of fixed links, labels, image loading, form constraints and keyboard submission.

## Debugging process

1. Created a deliberately malformed full document containing all nine required problem categories. Saved its SHA-256 hash before validation.
2. Inspected the source and recorded the problems in manual-diagnosis.md before running the checker.
3. Created a separate fixed.html and documented the repairs without editing broken.html.
4. Submitted the complete broken.html source to https://validator.w3.org/nu/ by HTTP POST with Content-Type text/html; charset=utf-8, requesting JSON and HTML output. The checker found 10 errors and one warning, including a fatal stop at line 35.
5. Submitted the complete corrected source to the same hosted checker. The final result contained no errors or warnings.
6. Rendered the unmodified HTML checker responses locally in Chromium with the checker's stylesheet, and captured full-page screenshots. These are screenshots of actual checker reports, not an invented success page or screenshots of the profile rendering. Browser address-bar chrome is not included.
7. Followed the fixed navigation links, checked IDs and labels, loaded the image, tested native form validation, and submitted a fictional example using the keyboard.
8. Confirmed the final broken.html hash still matches the original preserved fingerprint.

The initial fatal parser error limits the checker’s diagnosis. The single initial warning identifies the first occurrence of the duplicate ID. Missing language, the broken links, heading hierarchy and further form-label/closure problems are also included in the manual findings; they are not misrepresented as messages from the truncated initial checker report.

The initial and final JSON and HTML responses came from separate submissions of identical source bytes for each phase. Source hashes identify exactly which HTML documents were checked.

## Important distinctions

HTML rendering is not proof of conformance. Browsers can repair invalid nesting automatically. Conversely, a clean checker report cannot establish whether a relative file exists, a heading outline is useful, or an image description accurately communicates its purpose. This project includes manual inspection and browser checks alongside hosted W3C validation.

Some paragraph end tags may legally be omitted in HTML. In the deliberately broken paragraph/list example, the browser closes p when it sees ul, leaving the later explicit closing p unmatched. The missing div, fieldset and section closures are separate problems.

## Open the project

Download this folder and open fixed.html in a browser. Keep images/profile.svg in place. Open the Markdown table on GitHub, or in a Markdown reader. Open the PNG screenshots to inspect the initial and final results. Do not try to make broken.html valid: it is the preserved test case.

## Media and safety

The local SVG is original generic avatar artwork created for the exercise with assistance. It is not a real person’s photograph. No third-party personal media is used. The form uses GET for demonstration, so enter fictional details only: its values appear in the URL, and it sends no email or saved application. No passwords, tokens, keys or confidential applicant information are included.

validation/style.css is the hosted Nu HTML Checker's stylesheet, downloaded solely to render its saved reports accurately. It is evidence-supporting material, not styling added to fixed.html. The checker report HTML is generated by the W3C-hosted service. Attribution: https://validator.w3.org/nu/ and https://github.com/validator/validator . The source profile documents themselves use no CSS or JavaScript.

This exercise and its documentation were prepared with AI assistance. Review the source and explanations so you can explain each repair yourself.
